# AIGC 场景制作规则

用于把业务改造讲给非技术观众。保持判断与数据来自同一工作流模型；图片和视频只是表达层。

## 画什么

默认一张左右对照的叙事插画，每侧三幕：同一需求进入、角色如何处理、交付与异常去向。角色、订单、起止边界一致，显示交接和责任变化。每格只解释一件事，中文短标题，复杂字段与数值另列。

不要把演示模型当客户实绩。没有已证实瓶颈时，只展示交接和待查状态，不擅自加“浪费了3小时”。人留在场景里处理例外与确认，不用员工消失、现金堆积或货车飞驰暗示无依据收益。没有源头事实的环节标“待确认”。

可以用人物、工作台、消息、订单卡、仓库和异常标记帮助理解；不让模型绘制精确界面、完整控制流或唯一的数据图表。精确逻辑留在 HTML/SVG/Mermaid，数字采用可追溯、可校对的字幕或正文。

## 能力选择

| 宿主能力 | 实际交付 |
| --- | --- |
| 仅文本 | 同案例视觉故事、逐幕说明、图像提示词、视频分镜 |
| 有图像生成 | 前后场景插画；校对角色和异常责任，不把它称为已部署界面 |
| 有视频或确定性动画导出 | 按分镜制作可交付视频；先确认权限、时长和费用限制 |

不内置或指定收费服务，不静默请求 API Key，不因为缺少图像或视频工具中断诊断。使用者可拿制作稿去任意可用工具生成，核心技能仍能独立安装。

## 提示词骨架

明确用途是业务叙事插画，依次包含：观众与目标、同一案例、固定角色与场地、改造前的动作、改造后的动作、例外人工接手、未改变的现实约束、风格与画幅、准确短文案、禁止编造的收益。用户已有视觉风格时优先沿用。

精确指标写在独立的“后期字幕”区，包含来源状态、单位、适用条件与排除项；未知指标不填零。默认不将指标塞入生成式画面，避免误读或乱码。画面角落标“模拟场景，非实测”。

## 60 秒视频叙事

0–10秒介绍一笔具体需求；10–22秒展示原来的交接；22–36秒重放新处理方式；36–48秒显示例外与人工接手；48–60秒展示相同交付物及有条件的效果。不是把所有节点压成难以阅读的跑马灯。

脚本 storyboard 的输出是基础分镜，visuals 输出图像制作提示词。图片不等于视频、分镜不等于成片。发布前校验字幕、来源、角色、异常去向与报告一致；生成错误不能反过来修改业务事实。
